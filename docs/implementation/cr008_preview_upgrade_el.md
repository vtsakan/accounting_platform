# Αναβάθμιση υπάρχοντος VM και GitHub — CR008

Η νέα εντολή επιτρέπει την αναβάθμιση στην επαληθευμένη CR008. Επιλέχθηκε
**διατήρηση του ίδιου VM στα 4 GB και προσωρινά χωρίς νέες μεταφορτώσεις
συνημμένων**. Δεν γίνεται αλλαγή μεγέθους VM ούτε εγκατάσταση σαρωτή.

Το GitHub `main` παρατηρήθηκε στο `4a817c4` και το VM στην CR005, με 30
migrations. Η εικόνα `91ef03bf`, με περιεχόμενο `9a530ae7`, πέρασε 1.186/1.186
δοκιμές, 36 οικονομικές περιπτώσεις, πραγματικό antivirus, επαναφορά 61 πινάκων
και 10 συνθετικών αρχείων, καθώς και τον πραγματικό μηνιαίο worker. Η ίδια
εικόνα επαναχρησιμοποιείται χωρίς build ή επανάληψη της σουίτας εφαρμογής.
Τα 371 αρχεία εικόνας, οι 36 migrations και όλοι οι παλιοί έλεγχοι μένουν ίδια.

## Εκτέλεση στον υπολογιστή σας

```bash
bash ~/Downloads/accounting-platform-CR008-VM-GitHub/UPDATE_GITHUB_AND_VM.sh
```

Το `APPLY_CR008_VM.sh` κάνει μόνο Git/αρχεία. Ελέγχει την ακριβή πηγή, τη γνήσια
πλήρη αναφορά και την πραγματική ιστορία Git. Διατηρεί αποκλειστικά τις 16
πραγματικές αναφορές/δεσμεύσεις. Άγνωστες αλλαγές δεν γίνονται αυτόματα commit,
stash ή reset. Αν εκκρεμούν μόνο τα δύο ακριβή επιτυχή αρχεία `--record`,
καταχωρίζονται πρώτα από το υπάρχον αυστηρό εργαλείο καταγραφής.

Το UPDATE εκτελεί τους 39 ελέγχους εργαλείων, νέο έλεγχο μυστικών στην πραγματική
πηγή/ιστορία και δημοσιεύει την τοπική ιστορία με κανονικό fast-forward. Έπειτα
αναβαθμίζει το υπάρχον VM. Χρειάζονται οι ίδιες συνδέσεις GitHub/gcloud/IAP,
το τοπικό Docker και η ακριβής επιτυχημένη εικόνα. Δεν δημιουργούνται κωδικοί,
χρήστες, κλειδιά ή cloud πόροι. Η διακοπή διαρκεί μέχρι να ολοκληρωθούν οι δύο
επαναφορές και οι έλεγχοι ενεργοποίησης.

Απαιτείται το υπάρχον ανεξάρτητο αντίγραφο κλειδιού
`~/.config/totalaccounting/recovered-backup-age.key`. Άλλη θέση δίνεται μετά
το APPLY με την εντολή:

```bash
python3 tools/preview_cr008_release.py all --identity /απόλυτη/θέση/αντιγράφου.agekey
```

## Βάση, αντίγραφα και ενεργοποίηση

1. Επιβεβαιώνονται το ίδιο VM `e2-medium`, δίσκος, hostname, η τρέχουσα CR005,
   η διαθέσιμη μνήμη/χώρος και η ίδια υπηρεσία PostgreSQL και ουρά.
2. Παύουν οι χρονοδιακόπτες και σταματούν ομαλά scheduler, worker και HTTP
   εγγραφές. Λαμβάνεται κρυπτογραφημένο αντίγραφο της παγωμένης βάσης.
3. Δημιουργείται χωριστό αντίγραφο της **τρέχουσας** βάσης και μόνο αυτό
   μεταβαίνει από 30 σε 36 migrations. Η παλιά βάση παραμένει χωρίς αλλαγές.
   Συγκρίνονται όλες οι αρχικές στήλες/γραμμές, χρήστες, κωδικοί, MFA και
   συνεδρίες. Οι οκτώ νέοι πίνακες εργασιών, προφίλ και συνημμένων είναι κενοί.
4. Λαμβάνεται κρυπτογραφημένο αντίγραφο της νέας βάσης. Και τα δύο αντίγραφα
   επαναφέρονται εκτός VM με το ανεξάρτητο κλειδί. Ελέγχονται όλοι οι πίνακες
   της αρχικής βάσης και οι επιπλέον οκτώ, αναμενόμενα 53 και 61 αντίστοιχα.
5. Μετά την ταύτιση ενεργοποιούνται web, Redis, worker, ένας scheduler και
   ο ίδιος Caddy. Παραμένουν οι ίδιες θύρες, τέσσερις web workers, ένας worker
   διεργασίας και τα ίδια όρια μνήμης. Ελέγχονται δέκα στατικά αρχεία της ίδιας
   εικόνας, HTTPS, ελληνική σύνδεση, CSRF και αποκλεισμός νέων μεταφορτώσεων.

Οι εργασίες, η οικονομική/φορολογική καρτέλα και η δομή χαρακτηρισμών/συνημμένων
εγκαθίστανται. Το `ATTACHMENT_SCANNER_HOST` είναι ρητά κενό για web, worker
και scheduler. Η φόρμα συνημμένων παραμένει ορατή, αλλά η νέα μεταφόρτωση
απορρίπτεται με μήνυμα μη διαθεσιμότητας του ελέγχου ασφαλείας, χωρίς αποθήκευση.
Η ανάγνωση επιτρεπόμενου υπάρχοντος ιστορικού παραμένει διαθέσιμη.

Μετά την έναρξη εργασιών ή δημόσιων εγγραφών δεν επιτρέπεται αυτόματη
επιστροφή στην παλιά βάση. Η συνέχιση χρησιμοποιεί το ίδιο journal και τις
ίδιες αποδείξεις επαναφοράς. Πριν από νέες δημόσιες εγγραφές επιτρέπεται η
προβλεπόμενη επιστροφή στη διατηρημένη αρχική βάση. Δεν διαγράφεται journal
ή βάση για να δημιουργηθεί τεχνητά νέα προσπάθεια.

```bash
python3 tools/preview_cr008_release.py status
python3 tools/preview_cr008_release.py resume
```

Η επιτυχής αναφορά VM και μόνο το δικό της τμήμα κατάστασης καταχωρίζονται
στο Git και δημοσιεύονται με δεύτερο fast-forward. Η χωρητικότητα πραγματικού
φόρτου, η ανθρώπινη σύνδεση/MFA και οι 85 πλήρεις αποδοχές παραμένουν Pending.
Η απομονωμένη απόδειξη ανάκτησης συνημμένων διατηρείται· η πλήρης αποδοχή S38
παραμένει εκκρεμής. Η ενεργοποίηση live μεταφορτώσεων χρειάζεται μελλοντική
επιλογή χωρητικότητας και πραγματικό σαρωτή.
