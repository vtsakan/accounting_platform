# S31 — ελεγχόμενη σύγκριση workers

Η διάγνωση του χειριστή στις 19/11/2026, 11:02:52 ώρα Αθήνας έδωσε:

| p95 | 50 συνεδρίες HTTP | Καταγραφή Gunicorn | Μία συνεδρία HTTP μετά τον φόρτο |
| --- | ---: | ---: | ---: |
| Λίστα κινήσεων | 2,904 s | 0,062 s | 0,052 s |
| Λεπτομέρεια συναλλασσομένου | 3,038 s | 0,074 s | 0,065 s |
| Αναφορά 365 ημερών | 3,057 s | 0,234 s | 0,225 s |

Και τα 450 αιτήματα πέτυχαν. Οι μετρητές CPU quota throttling και συμβάντων
μνήμης παρέμειναν μηδέν. Στο διάστημα του probe ο web χρησιμοποίησε κατά μέσο
όρο περίπου 1,13 CPU και η βάση 0,77 CPU. Η επαναφορά και η εκκαθάριση πέρασαν.
Η επίσημη αναφορά S31 διατηρήθηκε αυτούσια με τεχνική κατάσταση **Failed**.

Η διαφορά στη συμπεριφορά με πολλές συνεδρίες υποστηρίζει την υπόθεση
αναμονής εξαιτίας της περιορισμένης ταυτόχρονης εξυπηρέτησης. Δεν αποτελεί
ακριβή μέτρηση ουράς ή απόδειξη αποκλειστικής αιτίας. Οι δύο κατανομές δεν
αντιστοιχίζονται ανά αίτημα και δεν αφαιρούμε τα p95. Οι μηδενικοί μετρητές
quota δεν αποκλείουν φόρτο στον υπολογιστή. Η επίσημη τεκμηρίωση του
[Gunicorn](https://gunicorn.org/design/) περιγράφει ένα εξυπηρετούμενο αίτημα
κάθε φορά ανά sync worker και προτείνει μέτρηση του αριθμού workers υπό φόρτο.

## Το νέο πείραμα

Μετά την εφαρμογή του συμπληρωματικού πακέτου:

```sh
cd ~/accountant_cloud/accounting_v5/accounting-platform
export PATH="$HOME/.local/bin:$PATH"
python3 tools/compare_s31_workers.py
```

Χρησιμοποιεί την ίδια υπάρχουσα εικόνα S30 και το ήδη ανακτημένο εξωτερικό
κλειδί age. Το προαιρετικό `--identity` επιλέγει άλλο υπάρχον ιδιωτικό αρχείο
κλειδιού. Ο κώδικας πρέπει να είναι καταχωρισμένος και καθαρός. Η προετοιμασία
και η εκτέλεση αφορούν αποκλειστικά τοπικό, νέο απομονωμένο συνθετικό έργο.

1. Δημιουργείται μία νέα συνθετική βάση, με τις υπάρχουσες διαδικασίες κλώνου,
   μετάβασης 20→26, οικονομικού κύκλου και ίδιου δείγματος φόρτου.
2. Ο web αναδημιουργείται με **2 sync workers** και εκτελείται η ίδια μέτρηση
   50 συνεδριών: 450 αιτήματα και τρεις εξαιρούμενες προθερμάνσεις.
3. Ο ίδιος web αναδημιουργείται με **4 sync workers**, στην ίδια βάση και με
   τους ίδιους πόρους, και η μέτρηση επαναλαμβάνεται.
4. Ο web αναδημιουργείται πάλι με **2 sync workers** και εκτελείται ο δεύτερος
   έλεγχος αναφοράς, ώστε να φαίνεται πιθανή μεταβολή φόρτου ή cache με τον χρόνο.
5. Ολοκληρώνεται η ίδια κρυπτογραφημένη επαναφορά και εκκαθάριση S31.

Σε κάθε συνθήκη παραμένουν οι ίδιες **2 CPU και 1 GiB RAM ανά web/βάση**,
το ίδιο σύνολο οικονομικών εγγραφών, οι 50 συνεδρίες και οι στόχοι 2/2/10 s.
Ελέγχονται οι πραγματικές ζωντανές διεργασίες και τα πραγματικά όρια Docker.
Η αρχική βάση δεν αναδημιουργείται ανάμεσα στις τρεις συνθήκες. Συγκρίνονται
όλοι οι πίνακες `accounting_*` πριν και μετά από κάθε μέτρηση, με εξαίρεση τους
δύο πίνακες συνθετικής κατάστασης αυθεντικοποίησης/MFA. Οι εγγραφές συνεδριών
και τελευταίας σύνδεσης ανήκουν στην αναμενόμενη συνθετική δραστηριότητα.

Συνολικά υπάρχουν **1.350 μετρούμενα HTTP αιτήματα**, εννέα εξαιρούμενες
προθερμάνσεις και οι πρόσθετες επεξηγηματικές παρατηρήσεις της προηγούμενης
διάγνωσης μετά από κάθε μέτρηση. Όλες οι αποτυχίες διατηρούνται. Δεν αθροίζουμε
τα δείγματα διαφορετικών συνθηκών για να εμφανίσουμε καλύτερο p95. Μετρώνται
επίσης οι CPU/affinity και ο γενικός φόρτος του υπολογιστή, χωρίς στοιχεία
δικτύου, ονόματα ανθρώπων, περιεχόμενο αποκρίσεων, SQL ή παραμέτρους.

## Ερμηνεία και όρια

Η κονσόλα εμφανίζει `S31-WORKERS-RESULT`, με ξεχωριστά αποτελέσματα για τις
τρεις συνθήκες και αναλογίες p95. Το πλήρες JSON αποθηκεύεται με δικαιώματα
0600 στο αγνοούμενο `private/s31/workers-<αναγνωριστικό>/comparison.json`.
Τα συνθετικά resources/μη κρυπτογραφημένα αρχεία αφαιρούνται. Τα κρυπτογραφημένα
συνθετικά αντίγραφα παραμένουν εκτός Git, όπως στις προηγούμενες πρόβες.

Η ακολουθία είναι μία μικρή, μη τυχαιοποιημένη σύγκριση. Διατηρούμε τους δύο
ελέγχους αναφοράς για να εκτιμήσουμε μεταβολές, χωρίς ισχυρισμό στατιστικής
βεβαιότητας. Αν οι τέσσερις workers βελτιώσουν τους χρόνους, αυτό υποστηρίζει
μια χωριστά αξιολογημένη αλλαγή συνθετικού runtime profile και πλήρη επίσημη
επανάληψη S31. Δεν αποτελεί αυτόματη επιλογή ρύθμισης ή αποδοχή χωρητικότητας VM.

Το αρχικό `r1_workload.json` εξακολουθεί να ορίζει δύο workers και ο επίσημος
επαληθευτής/αναφορά S31 παραμένουν αμετάβλητοι. Η έκδοση είναι **Blocked** και
οι 85 πλήρεις αποδοχές **Pending**. Το εργαλείο δεν επαναλαμβάνει τις 848/36
δοκιμές ή τον πραγματικό Redis που ήδη πέρασαν. Δεν γίνεται αλλαγή demo/VM,
ανθρώπινου λογαριασμού/MFA ή πραγματικών δεδομένων. Τα D05/D06/D07/G2 και η
ανθρώπινη αποδοχή εξακολουθούν να εκκρεμούν. Παραμένουμε στο S31.

Τα νέα εργαλεία είναι **Prepared**, με στατικούς ελέγχους από τον agent.
Εκτέλεση σύγκρισης από τον χειριστή: **Pending**. Στείλτε την έξοδο
`S31-WORKERS-RESULT` ή `S31-WORKERS-DIAG` για τη συνέχεια.
