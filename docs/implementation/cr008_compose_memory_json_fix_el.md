# CR008 — διόρθωση ανάγνωσης μνήμης στο Compose JSON

Η πραγματική ανανέωση 27b7fc8 πέρασε 101/101 ελέγχους και δημοσιεύτηκε στο
GitHub. Ο νέος κύκλος σταμάτησε στον έλεγχο plan, πριν από prepare, παύση
writers, backups και ενεργοποίηση υπηρεσιών. Το προηγούμενο αποτυχημένο
0586150 journal και το αρχικό ολοκληρωμένο CR008 παραμένουν διατηρημένα.

Η αιτία βρίσκεται στον έλεγχο της ρύθμισης, όχι στην τιμή του overlay:
το compose-go UnitBytes.MarshalJSON γράφει δεκαδικά bytes ως συμβολοσειρές.
Τα "201326592" και "402653184" δεν ισούνται με ακέραιους Python, παρότι
αντιστοιχούν ακριβώς στα απαιτούμενα 192 και 384 MiB. Ο έλεγχος αποδέχεται
πλέον και τις δύο ακριβείς αναπαραστάσεις. Άλλα όρια, bool, float, μονάδες,
κενά, μηδενικά ή απεριόριστα όρια εξακολουθούν να απορρίπτονται. Η τελική
αποδοχή διαβάζει ξεχωριστά τα πραγματικά Docker HostConfig/cgroup όρια.
Πηγή: https://github.com/compose-spec/compose-go/blob/main/types/bytes.go

Το APPLY αλλάζει μόνο Git/αρχεία. Κρατά ακριβές στιγμιότυπο του προηγούμενου
manifest, την υπάρχουσα αποκλειστική δέσμευση 19 πραγματικών αναφορών, όλα
τα 27 προηγούμενα δεσμευμένα αρχεία και τις 101 δοκιμαστικές μεθόδους.
Προστίθενται 14 έλεγχοι μορφής JSON και προϋποθέσεων επανάληψης (σύνολο 115).
Οι 824 αρχικές δεσμεύσεις, τα 371 αρχεία εικόνας, οι 36 migrations και οι
85 Pending αποδοχές παραμένουν ακριβώς ίδια. Το state.md δεν αντικαθίσταται.

Το UPDATE τρέχει τους ελέγχους και επιθεωρεί το memory status. Μόνο η ακριβής
εκκρεμής 27b7fc8 ρύθμιση χωρίς STATE/HOLD μπορεί να συνδεθεί στη διόρθωση,
αφού περάσει νέο πραγματικό plan στην ίδια βάση και με τα σωστά όρια.
Πριν από τη σύνδεση κρατιέται αποκλειστικό, ιδιωτικό, byte-identical αντίγραφο
της παλιάς τοπικής ρύθμισης. Εάν έχει ήδη αρχίσει prepare, το UPDATE σταματά
για επιθεώρηση· κανένα journal δεν διαγράφεται, επαναφέρεται ή μετονομάζεται.

Μετά το plan ακολουθεί η ήδη ελεγχόμενη διαδικασία της ίδιας τρέχουσας βάσης:
δύο ΦΡΕΣΚΑ κρυπτογραφημένα backups και ανεξάρτητες 61/61-table επαναφορές,
πραγματικό antivirus/EICAR, cgroup μετρητές χωρίς OOM, υγιής ουρά και δημόσιο
HTTPS/CSRF. Το VM παραμένει 4 GiB, scheduler 192/384 MiB. Δεν γίνεται image
build, migration, clone, resize ή αλλαγή χρηστών/MFA/κλειδιών. CR009 σε αναμονή.

Αυτή είναι προετοιμασία με στατικούς ελέγχους. Οι 115 δοκιμές και το νέο VM
runtime θα εκτελεστούν από τον χειριστή· δεν δηλώνεται νέα λειτουργική επιτυχία.
Σε διακοπή: python3 tools/preview_cr008_memory_release.py status
