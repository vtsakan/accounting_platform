## Τι αλλάζει στο VM

Στόχος παραμένει αποκλειστικά το `accounting-preview`, `europe-west1-b`,
project `accounting-514109`, με το υπάρχον disk και το
`https://totalaccounting.duckdns.org`. Δεν δημιουργείται νέο VM.

1. Ελέγχονται η τρέχουσα έκδοση S31A, ο δίσκος, τα έξι ενεργά services,
   τα δεσμευμένα υλικά πρόσβασης και η δυνατότητα ανεξάρτητης ανάκτησης.
2. Σταματούν scheduler, worker και οι HTTP εγγραφείς. Οι υπάρχουσες ουρές
   και τα volumes διατηρούνται. Ενεργή εργασία με lease σταματά την πρόοδο.
3. Λαμβάνεται κρυπτογραφημένο backup της **τρέχουσας** βάσης. Δημιουργείται
   νέο αντίγραφό της με διαφορετικό όνομα. Η τρέχουσα βάση παραμένει άθικτη.
4. Στο νέο αντίγραφο εφαρμόζονται οι migrations **26 → 28** με περιορισμένο
   ρόλο. Ελέγχονται όλες οι αρχικές στήλες και εγγραφές, κωδικοί, MFA και
   sessions. Προστίθεται μόνο ο κενός πίνακας σημειώσεων· οικονομικές
   καταχωρίσεις δεν δημιουργούνται από τη migration.
5. Λαμβάνεται κρυπτογραφημένο backup του νέου αντιγράφου. Και τα δύο backups
   επαναφέρονται εκτός VM με το υπάρχον ανεξάρτητο αντίγραφο του κλειδιού,
   συγκρίνονται όλοι οι δημόσιοι πίνακες και καθαρίζεται το προσωρινό plaintext.
6. Ενεργοποιούνται η νέα εφαρμογή, ο worker και ένας scheduler με τα ίδια όρια
   πόρων. Διατηρούνται τα durable volumes και τα ήδη εγκεκριμένα jobs.
7. Ελέγχονται HTTPS, ελληνική σύνδεση, CSRF, τα τρία υφιστάμενα static assets
   και το νέο CSS του ημερολογίου. Καταγράφεται νέο αποτέλεσμα VM και
   δημοσιεύεται στο GitHub με κανονικό commit/push.

Οι λογαριασμοί, ο ιδιοκτήτης, τα passwords, οι συσκευές MFA και τα κλειδιά
παραμένουν ως έχουν. Η πραγματική είσοδος του λογιστή με το δικό του MFA
παραμένει χειροκίνητος έλεγχος μετά την αναβάθμιση. Το release δεν εγκρίνει
αυτόματα R1/D05/D06/D07/G2 ή τις 85 πλήρεις αποδοχές απαιτήσεων.

## Κατάσταση και συνέχεια υπάρχουσας προσπάθειας

```bash
python3 tools/preview_cr004_release.py status
python3 tools/preview_cr004_release.py resume
```

Πριν ενεργοποιηθούν jobs ή HTTP στη νέα βάση, αποτυχία μπορεί να επιστρέψει
στα παλιά services και στην αρχική βάση. Από την ενεργοποίηση και μετά,
η διαδικασία διατηρεί τη νέα βάση και τα backups και συνεχίζει την ίδια
προσπάθεια. Δεν επιστρέφει αυτόματα σε παλιότερα δεδομένα.

Το υπάρχον ανεξάρτητο κλειδί προεπιλέγεται από
`~/.config/totalaccounting/recovered-backup-age.key`. Αν βρίσκεται αλλού:

```bash
python3 tools/preview_cr004_release.py all --identity /απόλυτη/διαδρομή/κλειδιού
```

Κλειδιά και ιδιωτικές ρυθμίσεις παραμένουν εκτός Git. Η προετοιμασία του agent
περιλαμβάνει στατικούς ελέγχους· η εκτέλεση Docker, GitHub και VM γίνεται από
τον χειριστή με τις παραπάνω εντολές.
