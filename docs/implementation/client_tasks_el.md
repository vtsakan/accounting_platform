# Εργασίες πελατών — CR006

Στην καρτέλα πελάτη γράφετε μια σημείωση και επιλέγετε **Να γίνει εργασία**.
Εμφανίζονται η ημερομηνία καταγραφής, η λήξη και η ανάθεση. Η καταγραφή και
ο δημιουργός μπαίνουν αυτόματα· προεπιλεγμένος υπεύθυνος είστε εσείς.
Μπορείτε να επιλέξετε άλλο ενεργό μέλος του ίδιου γραφείου.

Σε παλιά σημείωση επιλέγετε **Να γίνει εργασία**. Η αρχική σημείωση κρατά
ακριβώς το κείμενο, την ημερομηνία και τον συντάκτη της. Η συνδεδεμένη εργασία
έχει δικό της κείμενο και ιστορικό αλλαγών. Η ίδια σημείωση δεν δημιουργεί
δεύτερη εργασία με επανάληψη της υποβολής.

Στην αρχική εμφανίζονται **Οι ανοιχτές εργασίες μου**: πρώτα οι εκπρόθεσμες,
μετά οι σημερινές και οι επόμενες, με τις ημέρες που απομένουν. Η προθεσμία
υπολογίζεται με την ημερομηνία Ελλάδας. Ο ιδιοκτήτης έχει επιπλέον προβολή
**Όλες οι εργασίες γραφείου**. Οι σελίδες και τα σύνολα καλύπτουν όλα τα
αποτελέσματα, ακόμη κι όταν εμφανίζονται25 γραμμές ανά σελίδα.

Ο δημιουργός, ο υπεύθυνος και ο ιδιοκτήτης μπορούν να αλλάξουν περιγραφή,
λήξη ή ανάθεση και να ολοκληρώσουν/ανοίξουν ξανά μια εργασία. Κάθε ενέργεια
κρατά χρήστη, ώρα και έκδοση. Οι ολοκληρωμένες μένουν στην καρτέλα και στο
ιστορικό. Οι εργασίες έχουν μοβ ένδειξη στο ημερολόγιο· οι σημειώσεις μένουν
μπλε και οι οικονομικές εγγραφές κρατούν τα αρχικά τους χρώματα.

Όσο υπάρχει ανοιχτή εργασία, η αρχειοθέτηση του πελάτη απαγορεύεται.
Ολοκληρώστε πρώτα τις εργασίες του. Σε αρχειοθετημένο πελάτη οι κλειστές
εργασίες προβάλλονται· απαιτείται επαναφορά για αλλαγή ή εκ νέου άνοιγμα.

## Εφαρμογή και απομονωμένος έλεγχος

```bash
bash <<'SH'
set -euo pipefail
unzip -o ~/Downloads/accounting-platform-CR006-client-tasks.zip \
  -d ~/Downloads/accounting-platform-CR006-client-tasks
bash ~/Downloads/accounting-platform-CR006-client-tasks/APPLY_CR006.sh
cd ~/accountant_cloud/accounting_v5/accounting-platform
export PATH="$HOME/.local/bin:$PATH"
python3 tools/verify_cr006.py --record --host-dns
SH
```

Το APPLY εκτελεί μόνο Git/αρχεία, διατηρεί τις έντεκα πραγματικές αναφορές
και δεσμεύσεις της προηγούμενης έκδοσης και δεν ανανεώνει παλιά αποτυπώματα.
Η νέα εικόνα ελέγχεται σε απομονωμένη PostgreSQL17 με ολόκληρη τη σουίτα,
τις36 οικονομικές περιπτώσεις και τον πραγματικό worker/Redis/scheduler.
Οι0031/0032 εφαρμόζονται μόνο στον απομονωμένο έλεγχο.

Ο agent εκτελεί μόνο στατικούς ελέγχους. Το υπάρχον VM και το GitHub μένουν
στην επιτυχή CR005 μέχρι να περάσει ο νέος έλεγχος και να γίνει η αντίστοιχη
αναβάθμιση. Όλες οι85 πλήρεις αποδοχές παραμένουν Pending.
