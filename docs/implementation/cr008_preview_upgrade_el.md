# CR008: δοκιμαστικές μεταφορτώσεις στο υπάρχον VM των 4 GB

Η νέα απαίτηση αντικαθιστά την προηγούμενη επιλογή απενεργοποίησης συνημμένων.
Το ίδιο `e2-medium` διατηρεί 4 GB φυσικής RAM. Προστίθεται ιδιωτικός πραγματικός
σαρωτής antivirus και χρησιμοποιούνται 2 GB swap από τον υπάρχοντα δίσκο, ή
επαρκές υπάρχον swap. Η παράλληλη εκτέλεση περιορίζεται για δοκιμαστική χρήση.
Δεν αλλάζει μέγεθος VM, δεν δημιουργείται νέο VM και δεν γίνεται νέο build.

Η εικόνα `91ef03bf`, περιεχόμενο `9a530ae7`, παραμένει ίδια: 371 αρχεία, 36
migrations, πραγματικό προηγούμενο αποτέλεσμα 1.186/1.186 και 36 οικονομικές
περιπτώσεις, antivirus, κρυπτογραφημένη επαναφορά 61 πινάκων/10 αρχείων και
πραγματικός μηνιαίος worker. Αυτό δεν αποδεικνύει ακόμη τη νέα χωρητικότητα
των 4 GB· ο νέος έλεγχος γίνεται στο πραγματικό VM πριν την ενεργοποίηση.

## Εκτέλεση

Χρησιμοποιήστε το ενημερωμένο ZIP και τον χωριστό φάκελο `4GB-test`:

```bash
bash ~/Downloads/accounting-platform-CR008-VM-GitHub-4GB-test/UPDATE_GITHUB_AND_VM.sh
```

Το APPLY κάνει μόνο Git/αρχεία και δέχεται είτε τη γνήσια επιτυχή CR008 είτε
την ακριβή προηγούμενη προετοιμασία χωρίς μεταφορτώσεις. Διατηρεί αποκλειστικά
τις 16 πραγματικές αναφορές και δεσμεύσεις, χωρίς ανανέωση ή κατασκευή τοπικής
ιστορίας. Άγνωστες αλλαγές δεν γίνονται commit, stash ή reset. Αν εκκρεμούν μόνο
τα δύο ακριβή επιτυχή αρχεία `--record`, καταχωρίζονται πρώτα από τον υπάρχοντα
αυστηρό recorder. Ήδη διαμορφωμένη προσπάθεια cutover άλλου προφίλ διατηρείται
για έλεγχο και δεν επαναχρησιμοποιείται σιωπηρά.

Το UPDATE εκτελεί 52 ελέγχους εργαλείων, νέο έλεγχο μυστικών στην πραγματική
πηγή/ιστορία και κανονική δημοσίευση GitHub με fast-forward. Χρειάζονται οι
ίδιες συνδέσεις GitHub/gcloud/IAP, το τοπικό Docker και η ίδια επιτυχημένη
εικόνα. Δεν επαναλαμβάνει τις 1.186 δοκιμές εφαρμογής ούτε παράγει νέα εικόνα.

Απαιτείται το υπάρχον ανεξάρτητο αντίγραφο κλειδιού
`~/.config/totalaccounting/recovered-backup-age.key`. Εναλλακτική θέση:

```bash
python3 tools/preview_cr008_release.py all --identity /απόλυτη/θέση/αντιγράφου.agekey
```

## Προφίλ δοκιμών

| Υπηρεσία | Όριο RAM |
| --- | ---: |
| Web, δύο workers | 512 MiB |
| PostgreSQL, ίδιο container/process | 768 MiB |
| Redis, ίδια διατηρημένη ουρά | 192 MiB |
| Worker, μία διεργασία | 256 MiB |
| Ένας scheduler | 128 MiB |
| Caddy | 128 MiB |
| Ιδιωτικός σαρωτής | 2.560 MiB |

Ο σαρωτής έχει επιπλέον όριο συνολικής RAM+swap 4.096 MiB. Το swap παρέχει
περιθώριο για αιχμές και είναι πιο αργό από τη RAM. Τα όρια δεν αποτελούν
μέτρηση κατανάλωσης ούτε εγγύηση παραγωγικού φόρτου. Η αρχικοποίηση μπορεί
να διαρκέσει αρκετά λεπτά. Ξεκινήστε με 1–2 μικρά δοκιμαστικά αρχεία.

Το εργαλείο χρησιμοποιεί επαρκές υπάρχον swap ή δημιουργεί αποκλειστικά
`/srv/accounting/cr008-test.swap`, 2 GiB, root-only 0600, με δεσμευμένα inode/
device/size. Δεν αντικαθιστά άγνωστο αρχείο, δεν αλλάζει άλλα swap ή fstab και
δεν απενεργοποιεί τα όρια μνήμης/OOM. Το δικό του swap και οι υπογραφές
διατηρούνται για επόμενη εκκίνηση· δεν διαγράφονται αυτόματα.

Ο πραγματικός ClamD χρησιμοποιεί την ήδη ελεγμένη pinned εικόνα. Έχει μόνο
ιδιωτικό δίκτυο, χωρίς δημόσια θύρα, σύνδεση Internet, database ή κλειδιά της
εφαρμογής. Τα αρχεία περνούν μέσω ιδιωτικού stream και αποθηκεύονται μόνο
μετά από επιτυχή σάρωση. Τα ίδια permissions/MFA/CSRF και οι έλεγχοι τύπου,
μεγέθους και κρυπτογράφησης παραμένουν. Όριο αρχείου: 25 MiB. Όριο HTTP
σώματος: 28 MiB, ώστε να υπάρχει περιθώριο για τα πεδία της φόρμας.

Οι υπογραφές ενημερώνονται χωριστά με σταματημένο daemon, διατηρώντας τον
έλεγχο φόρτωσης βάσης, όλες τις ειδοποιήσεις και όλες τις υπογραφές. Ένας
timer κάνει σειριακή ενημέρωση καθημερινά στις 04:30 Europe/Athens με μικρή
τυχαία καθυστέρηση. Εκείνο το διάστημα οι μεταφορτώσεις μπορεί να απορρίπτονται
προσωρινά· η υπόλοιπη εφαρμογή λειτουργεί. Αποτυχία ενημέρωσης/σάρωσης ή πολύ
παλιές υπογραφές απορρίπτουν τη μεταφόρτωση χωρίς αποθήκευση. Χειροκίνητα:

```bash
python3 tools/preview_cr008_release.py scanner-refresh
```

## Βάση, αντίγραφα και πραγματική επαλήθευση

1. Επιβεβαιώνονται το ίδιο VM/δίσκος/hostname, η τρέχουσα CR005, τουλάχιστον
   6 GiB διαθέσιμου χώρου, πραγματική υποστήριξη memory/swap limits και RAM.
2. Scheduler, worker και HTTP εγγραφές σταματούν ομαλά. Λαμβάνεται
   κρυπτογραφημένο αντίγραφο της παγωμένης τρέχουσας βάσης.
3. Δημιουργείται χωριστό αντίγραφο και μόνο αυτό μεταβαίνει από 30 σε 36
   migrations. Η αρχική βάση και ο ίδιος PostgreSQL process παραμένουν.
   Συγκρίνονται όλες οι αρχικές στήλες/γραμμές, χρήστες, κωδικοί, MFA,
   συνεδρίες και οικονομικό ιστορικό. Οι οκτώ νέοι πίνακες πρέπει να είναι κενοί.
4. Ενημερώνονται υπογραφές, ξεκινά ο περιορισμένος ιδιωτικός σαρωτής και
   ελέγχονται πραγματικό καθαρό stream, επίσημη δοκιμή EICAR και απόρριψη
   χωρίς σαρωτή. Ο έλεγχος δεν δημιουργεί συναλλασσόμενο/συνημμένο ή άλλη
   επαγγελματική εγγραφή. Ελέγχονται πραγματική διαθέσιμη RAM/swap και OOM.
5. Λαμβάνεται κρυπτογραφημένο αντίγραφο της νέας βάσης. Και τα δύο backups
   επαναφέρονται εκτός VM με το ανεξάρτητο κλειδί, με όλους τους πίνακες
   της αρχικής βάσης και τους επιπλέον οκτώ, αναμενόμενα 53 και 61.
6. Μόνο μετά από αυτά ενεργοποιούνται τα επτά services, οι μεταφορτώσεις και
   οι παλιές εργασίες. Ελέγχονται οι ίδιες διατηρημένες ουρές, δύο πραγματικοί
   web workers, ένας scheduler, δέκα στατικά αρχεία, HTTPS/CSRF και scanner.

Μετά την έναρξη εργασιών ή δημόσιων εγγραφών δεν επιτρέπεται αυτόματη
επιστροφή στην παλιά βάση. Η συνέχιση κρατά το ίδιο journal και τις ίδιες
αποδείξεις επαναφοράς. Πριν από δημόσιες εγγραφές επιτρέπεται η προβλεπόμενη
επιστροφή στην διατηρημένη CR005. Δεν διαγράφεται βάση/journal για νέα προσπάθεια.

```bash
python3 tools/preview_cr008_release.py status
python3 tools/preview_cr008_release.py resume
```

Μετά την επιτυχία καταχωρίζονται μόνο η νέα πραγματική αναφορά VM και το
δικό της τμήμα κατάστασης και ακολουθεί δεύτερο fast-forward. Τα sealed bytes
των συνημμένων περιλαμβάνονται στα ίδια κρυπτογραφημένα backups βάσης. Η
επαλήθευση 4 GB είναι δοκιμαστική και εξαρτάται από το πραγματικό αποτέλεσμα·
η πλήρης χωρητικότητα D06, browser/MFA/business, S38 και οι 85 αποδοχές
παραμένουν εκκρεμείς. Ο agent έχει κάνει μόνο στατικούς ελέγχους.
